# 運用の口 (トリガー・キュー・スラッシュコマンド)

> 何が job を起こし、どう並び、どのコマンドで止め直せるか。
> 入口は [README](../../README.md)、導入手順は [SETUP.md](../../SETUP.md)。

- bot は `bots.<key>.effort` で推論量を指定できる。**値域はランタイムで違う** — claude は `low | medium | high | xhigh | max` (`--effort` へ渡る)、codex は `none | minimal | low | medium | high | xhigh | max` (隔離 `CODEX_HOME` の `model_reasoning_effort` になる)。短い返答や簿記的な作業の思考量を抑える用途のほか、codex 側は**モデルが受け付けない値を避ける**のにも要る (`gpt-5.5` は `max` を拒む → [codex ランタイム](codex-runtime.md))。未指定なら従来どおり (claude は `--effort` を渡さない / codex はユーザー `~/.codex/config.toml` の値を写す)
- bot は自分宛メンションに反応。他 bot の発言もトリガーになる (manager → worker の委譲がこれ)。bot 間ホップは既定 **12** 回で停止し、人間の発言でリセット (`limits.maxBotHops`。0 なら bot 起点では起動しない)
- **自分の発言は原則ここで捨てる。通るのは自己呼び出しの制御メッセージだけ** (`src/trigger.js` の `shouldIgnoreOwnMessage`)。判定は**完全一致** — 1 行目が `<@自分の ID>` ちょうどで、2 行目があれば契約タグ 1 個だけ。「本文のどこかに自分宛メンションがある」では通さない: verify の失敗出力・ツール軌跡・git 差分は無害化を通らずに投稿されるので、外部由来の文字列に bot ID が紛れただけで自己 job が湧いてしまう (→ [制御マーカー](control-markers.md))
- **返信でも起動**: 人間が bot の発言に Discord の返信で返すと、メンションなしでもその bot が動く (`src/trigger.js`)。他人・他 bot への返信、bot からの返信は対象外。返信しつつ本文で別の bot をメンションした場合はメンション先だけが動く
- **bot が誰かを呼べるのは制御フッターだけ**: 応答末尾の独立行 `[[handoff:ボットキー]]` / `[[notify:owner]]` が唯一の起動経路。平文の `@名前` は変換されない (→ [制御マーカー](control-markers.md))
- **人間を呼ぶ**: `config.secrets.json` に `ownerUserId` を書くと `[[notify:owner]]` が実メンションになる。裁定待ち・承認待ち・実機確認の依頼で使う (roles/*.md に規定)。未設定なら実行されない — `allowedUserIds` の先頭から推測はしない
- プロンプトには「そのボットが前回読んだ位置以降」のスレッド発言が transcript として前置される (他者の発言の見落とし防止)。セッションが無い / 使えない時 (初回・cwd 変更・セッション消失・codex) は履歴を遡り直し、その時だけ**自分の過去発言も含める** — resume が持っていない分を補うため
- transcript には文字数上限がある (`limits.transcriptCharBudget`・既定 80000)。**日常的に効かせる値ではなく暴発防止の安全弁**で、超えた時だけ遡り分を古い順に落とし「起点投稿を除く過去 N 件を省略」と明示する。起点投稿・トリガー以降の発言・既読カーソルからの未読差分は対象外 (落とすと既読位置だけ進んで恒久欠落するため)
- **セッションの切り替え** (claude の bot だけ): resume し続けたセッションは前の job の履歴をツール結果ごと毎リクエスト読み直す。job の終わりに文脈 (最後のリクエストの input + cache) が `limits.session.maxContextTokens` (既定 150000) を超えるか、同じセッションで `maxJobs` (既定 25) job に達したら、本文に「🧵 …次の job から新しいセッションで再開します」と 1 行出し、配送の後で同じセッションに**引き継ぎメモ**を 1 ターン書かせる (Discord には出ない)。次の job は resume せず、スレッドの発言を `transcriptCharBudget` (既定 30000 字) で作り直し、先頭に「前のセッションからの引き継ぎ」(タスク板・自分の直近の job・作業ツリーの git status・編集したファイル・メモ) を足して始める。チャンネルの `session` でキーごとに上書きでき、0 はその物差しで切らない。しきい値は `node scripts/session-metrics.mjs` で実データから測り直せる
- job キューはチャンネル設定の `cwd` を正規化した「レーン」単位。同一レーンは受付順に 1 本ずつ、別レーンは並走する。`⏳ (キュー待ち)` が付くのは自分のレーンが塞がっている時か同時実行上限に達した時だけ。全レーン合計の同時実行数は `limits.maxConcurrentJobs` で絞れる (未設定 = 無制限。サブスクのレート上限に当たるようなら設定する)
- **即時停止**: `/stop` — そのスレッドの実行中 job をプロセスツリーごと即 kill + 待機 job も取消。`/stop scope:all` は全体停止 (スレッド外で打った場合は止める対象のスレッドが無いので全体扱い)。セッション/既読は成功時のみ前進するので、停止後の再メンションで続きから
- **スレッド別の編成**: `/roster members:"worker reviewer"` — そのスレッドで呼べる bot を絞る (`data/roster.json`)。`all` で解除・`none` で handoff 禁止・省略すると現況の表示だけ。効くのは**次の job から**で、編成外は実行文脈の「呼べる相手」から消え、`[[handoff:...]]` で指定しても起動しない (理由はスレッドに ⚠️ で出る)。止まるのは **bot 間の委譲だけ**で、人間が直接メンションすれば編成外の bot も動く。未設定のスレッドはチャンネル既定 (下記) へ落ち、それも無ければ制限なし
- **チャンネル既定の編成**: `config.policy.json` の `channels.<name>.roster` に bot キーの配列を書くと、そのチャンネルのスレッドで既定として効く。`/roster` はスレッド単位なので**打ち忘れたスレッドは全員呼べる** — 勝手に呼ばれると困る相手がいるチャンネル (雑談用など) では既定が逆に働くので、その初期値をここに置く。スレッドの `/roster` はこれを上書きし、`/roster all` は「全員」ではなく**この既定へ戻る**。省略 = 制限なし・`[]` = そのチャンネルでは handoff 禁止。`bots` に無いキーは起動時に落ちる
- **自律運転の停止**: `/pause reason:"…"` — スケジューラの自律起動 (タスク着手・巡回・承認/レビューの召喚) を止める。`/resume` で再開。**実行中の job は殺さず、人間のメンション・handoff・自己呼び出しも従来どおり通る** (いま動いているものを止めるのは `/stop`)。応答には「いつ誰が止めたか」と理由が出る。状態は `data/pause.json` に永続するので**再起動しても止まったまま** — 止めた理由が残っているのに社会が動き出す、を防ぐ。停止中も日次予算の日付繰越だけは進む。自律運転を使っていないチャンネルには何の影響もない
- **再起動**: `/restart` — ブリッジが再起動する。反映されるのは**作業ツリーの現在のコードと `.env`** — git の状態はそのまま使われる
  - 実行中/待機中の job があるときの素の `/restart` は拒否され「実行中 N 件・待機 M 件」が返る。中断してでも再起動するなら `/restart force:true` — stop all 相当で中断し、最大 30 秒だけ中断完了を待ってから落ちる
  - `/stop` `/roster` `/pause` `/resume` `/proposals` `/inbox` `/review` `/status` `/retry` `/case` `/restart` は起動中の**全 bot に登録**される (`/stop` の候補が bot の数だけ出る)。停止は緊急操作なので、1 体が落ちていても別の bot 経由で打てる方を採っている — state はプロセス共有なのでどれを選んでも結果は同じ
  - コマンドは認可・チャンネル確認の直後に ACK (`deferReply`) してから job を止める。Windows の中断は同期 `taskkill /T /F` なので、job が多いと 3 秒の interaction 期限を超えて「応答なし」に見えてしまうため
  - 仕組み: 本体は終了コード **42** で終了し、`npm start` のラッパー (`scripts/run.mjs`) が spawn し直す。クラッシュ (42 以外) では再起動しない — 暴走ループと二重ログインを防ぐため。再起動が終わると元のチャンネルに `✅ 再起動完了` が出る
  - **二重起動は断る**: 起動時に `data/.lock` (pid と起動時刻) を取り、別のブリッジが動いている・確かめられない・中身が読めないときは lock の在処と pid を出して終了コード 1 で止まる (再起動されない)。持ち主が居ない残骸 (強制終了・pid の再利用) は警告して引き継ぐ。終了時 (`/restart` の 42 を含む) は自分の lock だけ消すので再起動は阻まれない。止まったときは、別のブリッジが居ないと確かめてから `data/.lock` を消して起動し直す
  - Ctrl+C / kill での停止時も、待機 job の ⏳ は `⏹ ブリッジ停止により取り消し` に直してから終了する (キューは in-memory なので待機 job は引き継がれない)
- **レビューの出し直し**: `/review [id]` — review のまま止まったタスクのレビュー依頼を作り直す。**タスクのスレッドで打つ** (対象はそのスレッドのタスク。`id` を書いたときは一致しないと断る)。判定を返せるのは task-review 契約を持った job だけなので、契約が失われたタスクは人間が出し直さないと誰も動かせない。出し直すと**未消費のレビュー契約は置き換えられる**。review 以外の状態と、`/pause` で自律運転を止めている間は拒否する
- **状況の一覧**: `/status` — このチャンネルの過去 24 時間を「完了 (何が変わったか・検証 OK/NG/記録なし) / 進行中 / 復旧待ち / 判断待ち / 運転 (pause・バックオフ・日次予算・job の終わり方)」で 1 通に出す。承認済みのタスクが自律運転の同時枠 (`maxConcurrentTasks`) の空き待ちで着手されていないときは、運転の行の「着手待ち」に枠を持っているタスク (id と状態、復旧待ち・要照合なら経過も) を添える。判定は `/inbox` と同じ。検証記録が無い完了は「不明」と書き、成功に数えない。定時通知は無い (明示の照会だけ)
- **止まった仕事の再開**: `/retry [id]` — in-progress / review のまま止まったタスクを**同じスレッド・同じブランチ・同じ作業ツリーの続き**として担当に起こし直す (タスクのスレッドで打つ)。in-progress は担当 worker へ再開メッセージ (前回の終わり方・残っている変更・残り job 予算・「reset しない・最初からやり直さない」の約束) を担当以外の bot から投げ、review は `/review` と同じ判定でレビュー担当を呼び直す。走っている・キュー待ち・承認待ち・起動直後 (猶予 5 分)・未消費の契約がある・pause 中・blocked・着手前・終端は断る (理由と次の操作を返す)。予算は勝手に増やさない (残 0 なら断る)。再起動をまたいだ要照合の job は、前プロセスの子プロセス (pid + 起動時刻) が居ないことを確かめてから起こす。連打しても 1 回 (`data/recovery.json` に再開世代を残す)
- **自動復旧**: `autonomy.recovery.mode` が `auto` (既定) のチャンネルでは、止まった通常タスク (復旧待ち・再起動やタイムアウトでの中断・要照合) を、猶予と間隔 (既定 5 分 / 5・15・30 分。直前の job の終わりと直前の再開要求の遅い方から数える) を過ぎてから上限 3 回まで `/retry` と同じ入口で**同じブランチ・同じ作業ツリーの続き**として起こし直す。失敗・verify NG・配送失敗も対象 (副作用が始まっていても続きから再開する)。起こさないのは人間の `/stop`・設定の不備 (role が読めない等)・org-apply の task。要照合は前プロセスの子が残っていないと確かめられたときだけ起こす。上限・pause・task の job 予算・チャンネルの日次予算を超えては起こさない。`observe` は判断をログに残すだけ、`off` は判定もしない。実行記録の台帳が信用できないときは全停止。起こさない・起こせなかった理由 (上限・予算・停止中・設定の不備・送信前の断り) は `/status`・`/inbox` の復旧待ちの行と 🛟 の通知の理由の先頭に `自動復旧: …` として出し、auto で自動が起こさない・起こせないと分かったら 🛟 を判断の種類ごとに 1 回だけ出し直す。タスクのスレッドが archive されていれば、🛟 はスレッドを起こさずに親チャンネルへ、1 行目 (🛟) の次に「#N のスレッド <#…> は archive されているのでこちらへ」の 1 行を挟んで出す。起動直後の最初の見回りは 🛟 を 1 周待たせて判断を載せた 1 通にするので、起動直後に自動が起こした・再開を予定に入れたタスクには 🛟 が出ない
- **裁定の受信箱**: `/inbox` — **作者を待っているものを 1 か所に並べる** (停止・質問 / 稟議 / 要人間 の 3 節・待たせている時間が長い順・1 行に「経過時間」と「それが止めているもの」)。載るのは人間の手が要る 3 系統だけ: `[[notify:owner]]` の停止通知 (`data/inbox.json`・**実メンションを送れたときだけ**記録する)・裁定待ちの org 提案 (`data/proposals.json` を描画時に読む)・`blocked` のタスク (`data/tasks.json` 同上)。**載らないもの**: process 裁定の事後通知 (決まったことの連絡で依頼ではない)、ツール権限の承認カード (再起動で失効するのが正しい短命設計と混ぜない)。**閉じるのは機械**で、そのスレッドに人間が発言した時点で停止通知が閉じる (ホップのリセットと同じ条件 — 既読ボタンは押させない)。別のスレッドで答えたときだけ `/inbox close:<id>` で手動で閉じる (`close` は文字列オプションなので、打ち方は `/inbox close:3`)。稟議と blocked は正本側の操作 (裁定カード / 復帰) で消えるので close の対象外。4 節目の**復旧待ち**は、in-progress / review のまま止まっている仕事 (verify NG 後の無実行・実行失敗・配送失敗・再起動で切れた job・記録が無くて走っていると言い切れないもの) を実行記録 (`data/job-runs.json`) から拾い、1 行に「状態: 理由 → 次の操作」を出す。走っている・キュー待ち・承認待ち・返信待ち・handoff 直後 (猶予 5 分) は載せない。人間が一言返しただけでは閉じず、仕事が動き出せば消える。同じ問題はタスクのスレッドへ 🛟 で 1 回だけ知らせる (自動復旧が起こさない・起こせないと分かったときの出し直しを除く)。何も待っていなければ「作者を待っているものはありません」の 1 行
  - 閉じた停止通知は、閉じてから 30 日 (実行記録の保持期間と同じ) を過ぎると起動時に `data/inbox.json` から消える。開いている entry・番号が最大の entry (次の番号の採番に使うので、閉じていても残す)・閉じた時刻が読めない entry は残す。消すものが無ければ書かない
- ツール許可はチャンネル設定の `"tools": "readonly"|"standard"|"full"` プリセット + `"toolsExtra"` (詳細は SETUP.md §0)。**未指定は `readonly`**・`permissionMode` 未指定は `default` (→ [セキュリティモデル](security-model.md))
- **足りない許可は Discord のボタンで足せる**: 拒否されたツール要求が承認カードになり、人間が承認したぶんだけ次の job から効く。`hooks: true` のチャンネルでは**実行中にその場で**カードが出て、押すまで job が止まり、押したら同じ job が続行する (→ [ツール権限の申請](tool-permissions.md))
- `cwd` の外を読ませたいチャンネルは `claudeAddDirs` に足す (claude の `--add-dir`。**読取専用にはできない** → [参照ディレクトリ](add-dir.md))
- 成果物へ向かわない場 (雑談) を作るチャンネルは `"structuredOutput": false`。役割文が `<!-- communitd-schema: ... -->` を宣言していても、そのチャンネルでは**委譲契約も報告様式も使わない**素の応答に戻る。**CLI の `--json-schema` を落とすだけでは足りない** — 役割文に残る「スキーマで検査する」の指示は消えないので、実行文脈にも「このチャンネルでは無効・プレーンテキストで返す」を出して打ち消す (実行文脈は役割文より上位 → 実行文脈)。**様式が振る舞いを決める**ので、「やったこと / 検証結果 / 残課題」を埋めさせる限りエージェントは仕事の顔から抜けない。省略 = 有効 (現状維持)・**切ると委譲の touch 制限も効かなくなる**ので、書込みを許したチャンネルで切るかは作者の判断 (→ [委譲契約](delegation-contract.md))
- Claude Code の hook 基盤を使うチャンネルだけ `"hooks": true` を書く。省略時は `--settings` 自体を渡さず従来挙動のまま (codex ランタイムは対象外)
- 完了時の機械検証は `"verify": "npm test"`（`hooks: true` 必須。ランタイムを問わず走る — 同一セッションへの差し戻しは Stop hook を持つ claude / pi だけで、hook の無い codex は 1 回目の NG が最終 NG）。失敗なら同一セッションへ既定で 1 回差し戻し、最終 NG は結果を投稿して handoff を止める。回数は `"verifyMaxRetries": 0..3`（既定 1）
- **レビューの証拠**: task ブランチが変更したテスト (`test/` の `*.test.js` の追加・変更) を、src を `git merge-base` の版へ一時的に戻した状態と HEAD の両方で 1 ファイルずつ走らせ、「変更前の src で落ちる / 落ちない / HEAD でも落ちる」の本数 (ファイル単位、exit code で判定) を出す。**落ちないテストは src の変更を検査していない疑い** (振る舞いを変えない整理なら落ちないのが正しい — 判定ではなく材料)。src を書き換えるので、**本体の作業ツリーと `src/` か `test/` が dirty な作業ツリーでは何も触らずに断る**。終わったら src と `test/` を HEAD へ戻す
  - **ファイルの中の本数**: HEAD と基点の回を `--test-reporter=tap` で走らせ、末尾の集計行 (`# tests` / `# pass` / `# fail`) を読んで 2 行目から `test/x.test.js: HEAD で通る 12 本のうち 変更前の src で落ちる 1・通る 11` を出す (通る = 基点で通った本数、落ちる = HEAD で通った本数の残り)。基点の TAP で最上位の `not ok` の名前がそのテストファイル自身なら読み込みで落ちた (基点に無い src や export を import する) として `test/x.test.js: 基点で読み込めず (HEAD で通る 7 本)`。**task が足したテスト**のうち通る本数を括弧で添える — `… 通る 11 (足した 2/3 通る)` (足した 3 本のうち 2 本が変更前の src でも通る。落ちる本数は書かない)、名前の無いファイルは `(足した 0 本)`、読み込めずは `(HEAD で通る 7 本のうち 足した 7 本)`。足したテスト = HEAD の回の TAP にあって、カバレッジの前の回 (基点の版のテストを基点の src で走らせた回) の TAP に無い名前 (足した・改名した)。名前は入れ子 (`# Subtest:` と字下げ) を親からつなぎ escape を外したもの、同じ名前は何本目かまで含めて突き合わせ、数えるのは HEAD で通ったテスト (describe の suite と SKIP / TODO は数えない)。足したファイル (A) は全部が足したテスト。**名前を変えずに中身だけ変えたテストは見分けない** (昔からあるテストと同じ扱いで、足したほうには入らない)。前の回が無い・前の回が時間切れや読み込みで落ちた・テストの stdout が 64 KB を超えた (頭が欠けて名前を取りこぼす) ファイルは括弧を付けずに従来の行のまま。実行回数は増えない (どの回も tap の stdout から読む)。足したテストのうち通る本数 (数えられないファイルは通る本数) の多い順に 5 件まで、残りは件数 — 読み込めずは通る 0 本として最後に並ぶので、畳んだ中にあれば `ほか 3 ファイル (うち基点で読み込めず 2)` と本数を添える (ハーネスの成績はこの本数と読み込めずの行を足して「落ちる」が全部読み込めずの提出を `落ちるが全部読み込めず` に数える)。HEAD でも落ちるファイル・集計の無い回 (撃った回など) は出さない。その後ろに、本数の行に出なかった落ちないファイルの名前 (`落ちない: …`) を出す。「落ちる」に数えたファイルのうち基点の回が時間切れ・起動失敗で終わったもの (テストの結果ではなく、集計も無いので本数の行に出ない) は、さらにその後ろに `基点で走り切らず: test/x.test.js (timeout after 600000ms)` の形で理由 (基点の回の `error`。`--json` では runs の base に残る) と並べる — 1 行目の数え方は変えず、上限に収まらなければ名前を「ほか n ファイル」に畳む (消したテストの名前の次)。集計を読むのは `--experimental-test-isolation=none` の Node 22.8 から — それより前は reporter を指定せず、本数の行の代わりに落ちないファイルの名前を全部出す。`--json` では runs の head / base の `tap` に残る
  - **消したテスト**: task が差分で消したテストファイル (`test/` の `*.test.js` の D。走らせない) と、変更したファイルから消えたテストの名前を、カバレッジの前 (変えた行の段があればその前) の 1 行に出す — `消したテスト: ファイル 2 (test/a.test.js, test/b.test.js)・消えた名前 4 本 (test/c.test.js 3, test/d.test.js 1)`。落ちるテストを消して verify を通すすり抜けは、走らせるテストの落ちる / 通るには何も残らないため。消えた名前 = カバレッジの前の回 (基点の版のテストを基点の src で走らせた回) の TAP にあって HEAD の回の TAP に無い名前 (消した・改名した。突き合わせ方は足したテストと同じで、数えるのは前の回のテスト — suite は数えず、前の回で通ったかは問わない)。前の回が無い・前の回か HEAD の回が時間切れや読み込みで落ちた・テストの stdout が 64 KB を超えたファイルは数えない (消したファイルは差分から出るので常に出す)。src の差分が無い task・変更したテストが無い task (テストを消して src だけ変えた) でも出し、何も消していなければ行を出さない。差分は `--no-renames` なので、テストファイルの改名は消したファイルと足したファイルの両方に出る。名前はそれぞれ 5 つまで (残りは `ほか n`。名前が消えたファイルは本数の多い順・同じなら名前順、0 本のファイルは出さない)。上限 (1200 字) に収まるまで消したファイルの名前 → 名前が消えたファイルの順に畳み、畳み切っても収まらなければファイルの中の本数の行を 1 件ずつ畳む (カバレッジの段は削らない)。実行回数は増えない。`--json` では `deletedTests` と `vanishedTests` (数えられたファイルごとの `{file, tests}`) に残る
  - **カバレッジの前後**: 同じ測定で、**変更したテストだけ**が覆った src の行を前後で比べる (`--experimental-test-coverage`。全スイートではない — 出す行にもそう書く)。後 = HEAD の回 (落ちる / 落ちないの HEAD の回に tap (22.8 より前は spec) と lcov の 2 つの reporter を付けて 1 回で済ませる)、前 = src と `test/` を補助ファイルごと基点の版へ戻して、基点にもあるテストを走らせたもの (task が足したテストは 0 扱い。「基点の src + HEAD のテスト」の回は前に使わない)。出すのは「task が触った src」∪「覆った行数が変わった src」で、`覆った行/全行 (%) → 同` (`なし` = そのテストでは読み込まれない — 触ったのに前後とも `なし` はテストが届いていない印) を覆った行数の差の大きい順に 5 件まで、残りは件数。src の差分が無い task (test/ だけの変更) でも測る。lcov の reporter は Node 20.11.0 / 21.2.0 から — それより前では「カバレッジは測れない (Node vX)」の 1 行で、落ちる / 落ちないはカバレッジ無しで従来どおり数える。lcov は一時ディレクトリへ出して読み、終わったら消す
  - **変えた行のうち通らない行**: src の差分がある task では、カバレッジの段の前に、task が変えた src の行のうち変更したテストが通らない行を src ごとに出す — `src/a.js: 変えた実行行 6 のうち通らない 2 (L120-125, L140)`。ファイル単位の % では大きい src に task の数行が埋もれ、書いた行に届かないテストは回帰を入れても全部通るため。変えた行 = 基点と HEAD の `git diff -U0` の `@@` の `+c,d` (HEAD の側。`d` の省略は 1、`+c,0` は消しただけで行なし、足した src は全行)、実行行 = そのうち HEAD の回の lcov の DA に出た行 (Node は空行・コメントにも DA を出すので、呼ばれない関数の中のコメント行も入る)、通らない = どの変更したテストも覆わなかった行 (テストごとの lcov の和集合)。HEAD の lcov に無い src (変更したテストが読み込まない — カバレッジの段の `なし` が印) と、変えた実行行の無い src (消しただけ) は出さない。通らない行の多い順に 5 件・範囲は 5 つまで (残りは `ほか n 範囲` / `ほか n ファイル`)。上限 (1200 字) に収まるまで、消したテストの名前の次に範囲 → src (1 件は残す) → ファイルの中の本数の行の順で畳む。diff は設定で形が変わらないよう `--inter-hunk-context=0`・接頭辞 `a/` `b/`・色 / 外部 diff / textconv なしで打つ。走らせる回は増えない (git diff が 1 回増えるだけ)。`--json` では measured の `coverage.changed` (`{path, changed, untested, ranges}`) に残る
  - **ブリッジが完了の回に測る**: 自律運転のタスクを worker の完了でレビューへ進めるとき、**レビュー担当を呼ぶ前に** task の作業ツリーで測り (基点は `autonomy.baseBranch`)、結果 (上限 1200 字) をレビューの依頼の本文 (落ちた検証の段と承認時の備考の間) と review 遷移の history note (`レビューの証拠: …`) に載せる。測るのは、作業ツリーで走る task で、チャンネルの `verify` に `node --test` と書かれているときだけ (別のテストランナーでは全部が「HEAD でも落ちる」の誤った証拠になる。`npm test` の中身は追わない)。子のテストには bot の token を渡さない。投げても断られても「測れませんでした — 理由」の行になるだけで、レビューへ進めること・召喚は変わらない。`/review` の出し直しと提案の適用では測らない。出し直し (自動復旧の呼び直しを含む) では、最後の review 遷移の note に証拠があればそれを、測った時刻と「その後の commit は反映していない」の 1 行を添えて依頼の本文に載せる (差し戻し前の周回の証拠は載せない)
  - **手で回す**: `node scripts/review-evidence.mjs --base <基点のブランチ> [--cwd <task の作業ツリー>] [--json]`。断ったとき・HEAD へ戻らなかったときは exit 1、変更したテストが無いときはその旨を 1 行で、src の差分が無いときはその旨とカバレッジの前後を返す (exit 0)。Ctrl-C (SIGINT / SIGTERM) の 1 回目は走っているテストを撃ち、src と `test/` を HEAD へ戻してから「停止で中断 — …」の 1 行で exit 1、2 回目は戻すのを待たずに抜ける (stderr に「戻さずに終了」と出るので `git status -- src test` で確かめる)
  - **過去の提出へ遡る**: `node scripts/review-evidence-backtest.mjs --channel <チャンネル> [--ids 108,148] [--tasks <tasks.json>] [--json]`。ボード (既定 `data/tasks.json`。読むだけ) のそのチャンネルの merge 済みタスクの review 遷移 (in-progress → review) を 1 回ずつ「提出」として、直後が review → in-progress なら差し戻し・review → merged なら通過と並べ、提出した時点の commit で上と同じ測定を走らせる。提出の commit は merge の note の `branch task/N@<tip>` から first-parent で辿った、遷移の時刻より前の最後の commit (差し戻しの後の修正は選ばない)、基点は merge commit の第 1 親。提出の commit が基点の祖先 (ブランチ上に無い)・note が読めない提出は理由付きで飛ばす。測るのは `os.tmpdir()` に作る detached な worktree 1 つで、`npm ci` は最初と `package-lock.json` が変わったときだけ、終わったら (失敗・停止でも) 消す。git を打つのはスクリプトのあるリポジトリなので、別リポジトリのチャンネルは測れない。提出ごとに `#108 提出 1/2・差し戻し・b80015f・<証拠の 1 行目>・1 秒` を出しながら進み、最後に証拠の種類 (落ちないあり / src の差分なし / 測れず…) × 差し戻し / 通過の集計を出す。1 提出に数秒〜数分かかる (測る提出が変えたテストの本数しだい)。停止したとき・worktree が残ったときは exit 1。Ctrl-C の 1 回目は測っている提出を戻して worktree を消してから、そこまでの行と集計を出す。2 回目は消さずに抜ける (stderr に「worktree を消さずに終了」— `git worktree list` で確かめる)
  - **変異を入れて殺すかを数える**: `node scripts/review-evidence-mutation.mjs --base <基点のブランチ> [--cwd <task の作業ツリー>] [--max 20] [--json]`。上の測定は変更の前後の 1 点でしか比べないので、変えた行に決まった変異を入れ、変更したテスト (上と同じ選び方) が殺すかを数える — `変異 20 通りのうち 生き残り 3 / 殺された 16 / 時間切れ 1 (対象 src 2 ファイル・変更したテスト 3 本・基点 abc1234 (main))` の後に生き残りを `src/x.js:120 === → !==` の形で 10 件まで (残りは `ほか n 通り`)。対象は基点から変えた行 (`git diff -U0` の HEAD の側) のある、HEAD にある `src/` の `.js`。変異は固定の 10 種 — `===` ↔ `!==`・`>=` → `<`・`<=` → `>`・`>` → `<=`・`<` → `>=`・`&&` ↔ `||`・`true` ↔ `false` (語は識別子の切れ目で、長い演算子を先に取る) — を 1 行の 1 箇所ずつ。`=>`・シフト (`>>` `<<` `>>>`)・`'…'` `"…"` `` `…` `` の中 (`${…}` の中も)・`//` の後・`/* */` の中・行頭が `//` `*` `/*` の行は入れ替えない。字句は行ごとに追い、正規表現リテラルは見分けない (中の引用符やバッククォートの後ろはその行だけ読み飛ばす)。変異は対象をパス順に全部挙げ、`--max` (既定 20、ファイルをまたいだ合計) を超えたら (ファイル, 行, 桁) の順の `floor(i × 全数 / max)` 番目を取る (同じ入力なら同じ選び方)。先に変異なしで 1 ファイルずつ走らせ、落ちるファイル (時間切れも) は外す (`変異なしでも落ちて外した n 本`)。変異ごとに src を書き換えて 1 ファイルずつ走らせ、最初に通らなかった回で決める — 時間切れなら時間切れ・それ以外は殺された、全部通れば生き残り — そのファイルを HEAD へ戻して次へ。**生き残りは判定ではない** (振る舞いの変わらない変異も混ざる)。1 通りごとに変更したテストを全部走らせうるので、テストの重さ × 変異の数だけかかる (変異が無限ループを作ると、そのファイルの時間切れ 10 分を待つ)。src の差分なし・変更したテストなし・変異 0 通り・変異なしでも全部落ちるはテストを走らせずに (最後のものは変異を入れずに) 理由の 1 行。門と後始末は上と同じ — 本体の作業ツリーと `src/` か `test/` が dirty な作業ツリーでは断り、終わったら (失敗・停止でも) src を HEAD へ戻して `src/` と `test/` が clean に戻らなければ exit 1。Ctrl-C の扱いも `review-evidence.mjs` と同じ。ブリッジ (レビューの依頼) へは配線していない
- `hooks: true` のチャンネルでは、その job が呼んだツールの種類・回数・主な引数が 🔧 の 1 行でスレッドに出る (→ [ツール軌跡](tool-trace.md))
- job が終わるたびに待ち時間・実行時間・終了理由が 1 行ログに出る (→ [計測ログ](metrics.md))
- **実行記録**: job 1 本の受付 → 起動 → モデル → 承認待ち → 検証 → 配送 → 終端と、どう終わったか (終了理由・止めた主体・次に動く主体) を `data/job-runs.json` に残す。受付を記録できない job は起動しない。再起動をまたいだ未終端の記録は「要照合」になり、前プロセスの子が残っていないと確かめるまで同じタスクを起こさない。終端記録は 30 日で消える。終端記録の `evidence` には job の重さとして、所要 (`runMs`、計測ログの run と同じ値)・verify の試行の所要の合計 (`verifyMs`、verify の無い job は null)・verify の試行回数 (`verifyAttempts`、Stop hook の差し戻しぶんを含む。verify の無い job・検証の途中で止めた job は null)・実消費のトークン (`tokens` = `{ input, cacheRead, cacheWrite, output }`、usage を返さないランタイムと起動前に失敗した job は null) も残る — 添えるだけで判定・門には使わず、この鍵が無い古い記録は null として読む。ハーネスの成績 (`node scripts/harness-report.mjs`、`--json` にも載る) は、版の判定と同じ job を bot の版 × job 種別 (task-work = タスクの job / review = レビューの契約 / approval = 承認の契約 / その他) に分け、tool 呼び出し (記録の無い job は外す) と所要分 (起動 → 終端。どちらか無ければ外す) の中央値と、今の版 ← 判定と同じ前の版の比を添える — 判定・改訂の巡回の門・起動文には入れない。版の行には、提出 (`next: reviewer` で終わったタスクの job) が 1 回で通った本数と割合 (verify 1 回・差し戻し / 封鎖なし・merge 時の指摘 0) と、通らなかった内訳 (再試行・指摘・差し戻し。重なりは各々に数える) も添える。merge は差し戻しと同じく、その遷移の前に終わった最後の提出へ結ぶ。verify の回数か merge 時の指摘の件数が分からない提出とレビュー中の提出は分母から外し (0 とは読まない)、測れた提出の無い版には添えない — これも判定には入れない
- **終わったタスクのアーカイブ**: merged / dropped になってから 30 日 (実行記録の保持期間と同じ) を過ぎたタスクは、起動時と 1 日 1 回、`data/tasks.json` から終わった月 (JST) ごとの `data/archive/tasks-YYYY-MM.json` (ボードと同じ id → タスクの形) へ移る。終わった時刻は履歴の merged / dropped の行で見る (`updatedAt` ではない)。残すのは終端でないタスク (止まったままのものも)・番号が最大のタスク (次の番号の採番に使うので、終わっていても残す)・終わった時刻が読めないタスク。アーカイブへ書いてからボードから消すので、途中で落ちても両方に残るだけ。読めない月のファイルには書かず、その月の分はボードに残してログに出す。移したタスクはボードから見えなくなる — そのスレッドで呼ばれてもタスクの情報は付かず、役割文の改訂で名指ししても解き直せず、企画の巡回とスカウトに見せる主題の進み具合 (merged の数) と重さの勘定からも抜ける (主題の経緯は `docs/themes.md` に残る)。集計のスクリプト (`kt-metrics`・`harness-report`・`review-evidence-backtest`) はボードの隣の `archive/` も読む (同じ id はボードの方を採る)
- **起動の記録と回し方の成績**: ブリッジは起動するたびに (二重起動の確認の後・Discord へのログインの前)、起動時刻・その時点の git HEAD・branch・pid を `data/boots.json` へ古い順に足し、新しい 200 件を残す (稼働中の版はほかの台帳に残らない — 作業ツリーの HEAD は merge で進む)。HEAD が 40 桁の hex でない・git が読めないときは null、detached の branch は null で残す。台帳が壊れている・`boots` が配列でないときと書けないときは書かずにログ 1 行で、起動は止めない。回し方の成績は `node scripts/loop-report.mjs --channel <チャンネル名> [--since YYYY-MM-DD] [--until YYYY-MM-DD] [--json] [--data <dir>] [--policy <file>]` で出す (読むだけ。既定の期間は今日を含む 7 暦日 (JST)。`--channel` は必須で、知らないオプションと設定に無いチャンネルは断る)。① 巡回 (スカウト・企画・改訂の bot ごとに日別の本数・提案 0 件の本数・tool 呼び出しの合計と中央値) ② 段の待ち (期間内に merged のタスクが承認・着手・作業・レビューに居た時間の中央値 — 差し戻しで戻った分は足し、blocked は入れない・差し戻しの回数・merge → 次の起票) ③ 日次 (job 数・自律起動 = 着手 + 巡回 + 自動復旧と日次上限・上限に届いた時刻と止まった時間。実行記録・ボード・再開の台帳から数え直し、発議は含まない) ④ 配備 (最新の起動の HEAD から基点ブランチへ未配備の merge の本数と最古の時刻) と受信箱の開いた用件を、1900 字以内の文にする。④ はチャンネルの作業場所がブリッジ本体と同じリポジトリのときだけ数え (違えば「対象外」)、`data/boots.json` が無い (配備前) ときは 0 本とせず「起動の記録なし — ④ は読めない」と出す。台帳は kt-metrics と同じ読み方 (無い・壊れているを 0 件にしない) で、ボードはアーカイブも読む。企画の巡回の起動文はこれを「読む」に並べ、回し方の振り返りでは `node -e` で数え直さずにこの数字を引かせる。判定・門には使わない
- **作業中の進捗**: `⚙️ 作業中…` は 30 秒おきに「段階 / 経過 / ツール件数 / 最後に完了したツール」へ書き換わる (`hooks: true` のチャンネル。変わったときだけ編集し、承認待ちの 🔐 は上書きしない)
