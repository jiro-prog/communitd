# 運用の口 (トリガー・キュー・スラッシュコマンド)

> 何が job を起こし、どう並び、どのコマンドで止め直せるか。
> 入口は [README](../../README.md)、導入手順は [SETUP.md](../../SETUP.md)。

- Claude bot は `bots.<key>.effort` に `low | medium | high | xhigh | max` を指定できる。短い返答や簿記的な作業の思考量を抑える用途で、未指定なら `--effort` を渡さず従来どおり
- bot は自分宛メンションに反応。他 bot の発言もトリガーになる (manager → worker の委譲がこれ)。bot 間ホップは既定 **12** 回で停止し、人間の発言でリセット (`limits.maxBotHops`。0 なら bot 起点では起動しない)
- **自分の発言は原則ここで捨てる。通るのは自己呼び出しの制御メッセージだけ** (`src/trigger.js` の `shouldIgnoreOwnMessage`)。判定は**完全一致** — 1 行目が `<@自分の ID>` ちょうどで、2 行目があれば契約タグ 1 個だけ。「本文のどこかに自分宛メンションがある」では通さない: verify の失敗出力・ツール軌跡・git 差分は無害化を通らずに投稿されるので、外部由来の文字列に bot ID が紛れただけで自己 job が湧いてしまう (→ [制御マーカー](control-markers.md))
- **返信でも起動**: 人間が bot の発言に Discord の返信で返すと、メンションなしでもその bot が動く (`src/trigger.js`)。他人・他 bot への返信、bot からの返信は対象外。返信しつつ本文で別の bot をメンションした場合はメンション先だけが動く
- **bot が誰かを呼べるのは制御フッターだけ**: 応答末尾の独立行 `[[handoff:ボットキー]]` / `[[notify:owner]]` が唯一の起動経路。平文の `@名前` は変換されない (→ [制御マーカー](control-markers.md))
- **人間を呼ぶ**: `config.secrets.json` に `ownerUserId` を書くと `[[notify:owner]]` が実メンションになる。裁定待ち・承認待ち・実機確認の依頼で使う (roles/*.md に規定)。未設定なら実行されない — `allowedUserIds` の先頭から推測はしない
- プロンプトには「そのボットが前回読んだ位置以降」のスレッド発言が transcript として前置される (他者の発言の見落とし防止)。セッションが無い / 使えない時 (初回・cwd 変更・セッション消失・codex) は履歴を遡り直し、その時だけ**自分の過去発言も含める** — resume が持っていない分を補うため
- transcript には文字数上限がある (`limits.transcriptCharBudget`・既定 80000)。**日常的に効かせる値ではなく暴発防止の安全弁**で、超えた時だけ遡り分を古い順に落とし「起点投稿を除く過去 N 件を省略」と明示する。起点投稿・トリガー以降の発言・既読カーソルからの未読差分は対象外 (落とすと既読位置だけ進んで恒久欠落するため)
- job キューはチャンネル設定の `cwd` を正規化した「レーン」単位。同一レーンは受付順に 1 本ずつ、別レーンは並走する。`⏳ (キュー待ち)` が付くのは自分のレーンが塞がっている時か同時実行上限に達した時だけ。全レーン合計の同時実行数は `limits.maxConcurrentJobs` で絞れる (未設定 = 無制限。サブスクのレート上限に当たるようなら設定する)
- **即時停止**: `/stop` — そのスレッドの実行中 job をプロセスツリーごと即 kill + 待機 job も取消。`/stop scope:all` は全体停止 (スレッド外で打った場合は止める対象のスレッドが無いので全体扱い)。セッション/既読は成功時のみ前進するので、停止後の再メンションで続きから
- **スレッド別の編成**: `/roster members:"worker reviewer"` — そのスレッドで呼べる bot を絞る (`data/roster.json`)。`all` で解除・`none` で handoff 禁止・省略すると現況の表示だけ。効くのは**次の job から**で、編成外は実行文脈の「呼べる相手」から消え、`[[handoff:...]]` で指定しても起動しない (理由はスレッドに ⚠️ で出る)。止まるのは **bot 間の委譲だけ**で、人間が直接メンションすれば編成外の bot も動く。未設定のスレッドはチャンネル既定 (下記) へ落ち、それも無ければ制限なし
- **チャンネル既定の編成**: `config.policy.json` の `channels.<name>.roster` に bot キーの配列を書くと、そのチャンネルのスレッドで既定として効く。`/roster` はスレッド単位なので**打ち忘れたスレッドは全員呼べる** — 勝手に呼ばれると困る相手がいるチャンネル (雑談用など) では既定が逆に働くので、その初期値をここに置く。スレッドの `/roster` はこれを上書きし、`/roster all` は「全員」ではなく**この既定へ戻る**。省略 = 制限なし・`[]` = そのチャンネルでは handoff 禁止。`bots` に無いキーは起動時に落ちる
- **自律運転の停止**: `/pause reason:"…"` — スケジューラの自律起動 (タスク着手・巡回・承認/レビューの召喚) を止める。`/resume` で再開。**実行中の job は殺さず、人間のメンション・handoff・自己呼び出しも従来どおり通る** (いま動いているものを止めるのは `/stop`)。応答には「いつ誰が止めたか」と理由が出る。状態は `data/pause.json` に永続するので**再起動しても止まったまま** — 止めた理由が残っているのに社会が動き出す、を防ぐ。停止中も日次予算の日付繰越だけは進む。自律運転を使っていないチャンネルには何の影響もない
- **再起動**: `/restart` — ブリッジが再起動する。反映されるのは**作業ツリーの現在のコードと `.env`** — git の状態はそのまま使われる
  - 実行中/待機中の job があるときの素の `/restart` は拒否され「実行中 N 件・待機 M 件」が返る。中断してでも再起動するなら `/restart force:true` — stop all 相当で中断し、最大 30 秒だけ中断完了を待ってから落ちる
  - `/stop` `/roster` `/pause` `/resume` `/proposals` `/inbox` `/review` `/status` `/retry` `/case` `/restart` は起動中の**全 bot に登録**される (`/stop` の候補が bot の数だけ出る)。停止は緊急操作なので、1 体が落ちていても別の bot 経由で打てる方を採っている — state はプロセス共有なのでどれを選んでも結果は同じ
  - コマンドは認可・チャンネル確認の直後に ACK (`deferReply`) してから job を止める。Windows の中断は同期 `taskkill /T /F` なので、job が多いと 3 秒の interaction 期限を超えて「応答なし」に見えてしまうため
  - 仕組み: 本体は終了コード **42** で終了し、`npm start` のラッパー (`scripts/run.mjs`) が spawn し直す。クラッシュ (42 以外) では再起動しない — 暴走ループと二重ログインを防ぐため。再起動が終わると元のチャンネルに `✅ 再起動完了` が出る
  - Ctrl+C / kill での停止時も、待機 job の ⏳ は `⏹ ブリッジ停止により取り消し` に直してから終了する (キューは in-memory なので待機 job は引き継がれない)
- **レビューの出し直し**: `/review [id]` — review のまま止まったタスクのレビュー依頼を作り直す。**タスクのスレッドで打つ** (対象はそのスレッドのタスク。`id` を書いたときは一致しないと断る)。判定を返せるのは task-review 契約を持った job だけなので、契約が失われたタスクは人間が出し直さないと誰も動かせない。出し直すと**未消費のレビュー契約は置き換えられる**。review 以外の状態と、`/pause` で自律運転を止めている間は拒否する
- **状況の一覧**: `/status` — このチャンネルの過去 24 時間を「完了 (何が変わったか・検証 OK/NG/記録なし) / 進行中 / 復旧待ち / 判断待ち / 運転 (pause・バックオフ・日次予算・job の終わり方)」で 1 通に出す。判定は `/inbox` と同じ。検証記録が無い完了は「不明」と書き、成功に数えない。定時通知は無い (明示の照会だけ)
- **止まった仕事の再開**: `/retry [id]` — in-progress / review のまま止まったタスクを**同じスレッド・同じブランチ・同じ作業ツリーの続き**として担当に起こし直す (タスクのスレッドで打つ)。in-progress は担当 worker へ再開メッセージ (前回の終わり方・残っている変更・残り job 予算・「reset しない・最初からやり直さない」の約束) を担当以外の bot から投げ、review は `/review` と同じ判定でレビュー担当を呼び直す。走っている・キュー待ち・承認待ち・起動直後 (猶予 5 分)・未消費の契約がある・pause 中・blocked・着手前・終端は断る (理由と次の操作を返す)。予算は勝手に増やさない (残 0 なら断る)。再起動をまたいだ要照合の job は、前プロセスの子プロセス (pid + 起動時刻) が居ないことを確かめてから起こす。連打しても 1 回 (`data/recovery.json` に再開世代を残す)
- **自動復旧 (限定)**: `autonomy.recovery.mode` が `auto` のチャンネルでは、止まった通常タスクのうち**副作用が始まっていないと実行記録で確認できるもの** (モデルの子プロセスが起動していない失敗、または hooks で軌跡が読めてツール 0 件・git 差分なし) だけを、猶予と間隔 (既定 5 分 / 15 分) を過ぎてから上限 2 回まで `/retry` と同じ入口で起こし直す。API エラー・タイムアウト・trace 不在だけでは副作用なしと判定しない。verify NG・配送失敗・要照合・人間の停止・org-apply の task は自動では起こさない (手動 `/retry`)。既定は `observe` (判断をログに残すだけ)。実行記録の台帳が信用できないときは全停止
- **裁定の受信箱**: `/inbox` — **作者を待っているものを 1 か所に並べる** (停止・質問 / 稟議 / 要人間 の 3 節・待たせている時間が長い順・1 行に「経過時間」と「それが止めているもの」)。載るのは人間の手が要る 3 系統だけ: `[[notify:owner]]` の停止通知 (`data/inbox.json`・**実メンションを送れたときだけ**記録する)・裁定待ちの org 提案 (`data/proposals.json` を描画時に読む)・`blocked` のタスク (`data/tasks.json` 同上)。**載らないもの**: process 裁定の事後通知 (決まったことの連絡で依頼ではない)、ツール権限の承認カード (再起動で失効するのが正しい短命設計と混ぜない)。**閉じるのは機械**で、そのスレッドに人間が発言した時点で停止通知が閉じる (ホップのリセットと同じ条件 — 既読ボタンは押させない)。別のスレッドで答えたときだけ `/inbox close:<id>` で手動で閉じる (`close` は文字列オプションなので、打ち方は `/inbox close:3`)。稟議と blocked は正本側の操作 (裁定カード / 復帰) で消えるので close の対象外。4 節目の**復旧待ち**は、in-progress / review のまま止まっている仕事 (verify NG 後の無実行・実行失敗・配送失敗・再起動で切れた job・記録が無くて走っていると言い切れないもの) を実行記録 (`data/job-runs.json`) から拾い、1 行に「状態: 理由 → 次の操作」を出す。走っている・キュー待ち・承認待ち・返信待ち・handoff 直後 (猶予 5 分) は載せない。人間が一言返しただけでは閉じず、仕事が動き出せば消える。同じ問題はタスクのスレッドへ 🛟 で 1 回だけ知らせる。何も待っていなければ「作者を待っているものはありません」の 1 行
- ツール許可はチャンネル設定の `"tools": "readonly"|"standard"|"full"` プリセット + `"toolsExtra"` (詳細は SETUP.md §0)。**未指定は `readonly`**・`permissionMode` 未指定は `default` (→ [セキュリティモデル](security-model.md))
- **足りない許可は Discord のボタンで足せる**: 拒否されたツール要求が承認カードになり、人間が承認したぶんだけ次の job から効く。`hooks: true` のチャンネルでは**実行中にその場で**カードが出て、押すまで job が止まり、押したら同じ job が続行する (→ [ツール権限の申請](tool-permissions.md))
- `cwd` の外を読ませたいチャンネルは `claudeAddDirs` に足す (claude の `--add-dir`。**読取専用にはできない** → [参照ディレクトリ](add-dir.md))
- 成果物へ向かわない場 (雑談) を作るチャンネルは `"structuredOutput": false`。役割文が `<!-- communitd-schema: ... -->` を宣言していても、そのチャンネルでは**委譲契約も報告様式も使わない**素の応答に戻る。**CLI の `--json-schema` を落とすだけでは足りない** — 役割文に残る「スキーマで検査する」の指示は消えないので、実行文脈にも「このチャンネルでは無効・プレーンテキストで返す」を出して打ち消す (実行文脈は役割文より上位 → 実行文脈)。**様式が振る舞いを決める**ので、「やったこと / 検証結果 / 残課題」を埋めさせる限りエージェントは仕事の顔から抜けない。省略 = 有効 (現状維持)・**切ると委譲の touch 制限も効かなくなる**ので、書込みを許したチャンネルで切るかは作者の判断 (→ [委譲契約](delegation-contract.md))
- Claude Code の hook 基盤を使うチャンネルだけ `"hooks": true` を書く。省略時は `--settings` 自体を渡さず従来挙動のまま (codex ランタイムは対象外)
- 完了時の機械検証は `"verify": "npm test"`（`hooks: true` 必須・claude ランタイム専用、codex は対象外）。失敗なら同一セッションへ既定で 1 回差し戻し、最終 NG は結果を投稿して handoff を止める。回数は `"verifyMaxRetries": 0..3`（既定 1）
- `hooks: true` のチャンネルでは、その job が呼んだツールの種類・回数・主な引数が 🔧 の 1 行でスレッドに出る (→ [ツール軌跡](tool-trace.md))
- job が終わるたびに待ち時間・実行時間・終了理由が 1 行ログに出る (→ [計測ログ](metrics.md))
- **実行記録**: job 1 本の受付 → 起動 → モデル → 承認待ち → 検証 → 配送 → 終端と、どう終わったか (終了理由・止めた主体・次に動く主体) を `data/job-runs.json` に残す。受付を記録できない job は起動しない。再起動をまたいだ未終端の記録は「要照合」になり、前プロセスの子が残っていないと確かめるまで同じタスクを起こさない。終端記録は 30 日で消える
- **作業中の進捗**: `⚙️ 作業中…` は 30 秒おきに「段階 / 経過 / ツール件数 / 最後に完了したツール」へ書き換わる (`hooks: true` のチャンネル。変わったときだけ編集し、承認待ちの 🔐 は上書きしない)
