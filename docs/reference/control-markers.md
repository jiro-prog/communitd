# 制御マーカー

> bot 同士の呼び出し・人間への通知・画像添付を決める、応答末尾の独立行。
> 入口は [README](../../README.md)、導入手順は [SETUP.md](../../SETUP.md)。

モデルの応答からブリッジへの指示は、**行頭で独立した 1 行**のマーカーだけを通す。
文法は 3 つとも同じ族で、解釈は `src/mentions.js` に一本化してある
(この文法は `roles/*.md` にも書いてある — **変えるときは両方直すこと**)。

| マーカー | 効果 | 置ける場所 |
| --- | --- | --- |
| `[[attach: 相対パス.png]]` | その画像を添付して送る | 本文中どこでも (複数可) |
| `[[handoff:ボットキー]]` | その bot を呼ぶ (キーは `config.policy.json` の `bots` のキー) | 末尾の制御フッター |
| `[[notify:owner]]` | 作者 (`ownerUserId`) へ通知する | 末尾の制御フッター |

- **平文の `@名前` は誰も呼ばない。** 以前は本文中の平文の呼び名 (bot の表示名や作者の呼び名) を実メンションへ変換していたが、
  「`@<名前>` と書くと起動する」と説明しただけでその bot が起動するなど、例文・引用でそのまま暴発した。
  いま起動を決めるのは制御フッターだけで、平文の呼び名は検出しても変換せず「呼べていない」旨を警告する
- **制御フッター**は本文末尾から遡って「空行かマーカー行」だけが続く範囲。`[[attach: ...]]` と並べて置ける
- **フッターは 1 通に 1 個だけ。** 2 個あるとどれも実行しない (どちらを意図したか決められないため)。
  未知の宛先・編成外・未起動・`ownerUserId` 未設定も同じく実行しない — いずれも理由をスレッドへ ⚠️ で出す
- **自分のキーを書くと自己呼び出し** — 同じ担当がもう一度起動して続きをやる。job がそこで一度終わるので、
  verify が走り・報告がスキーマ検査され・スレッドに区切りが残り・人間が割り込める。長い作業を
  「調査 → 実装 → 検証」と区切るための道具。**既定では別枠の上限を置かず**、bot 間ホップの枠 (12) で止まる —
  暴走が見えたときだけ `limits.maxSelfHops` で絞る (`0` なら機能ごと切れる)。別の担当が動くか人間が発言すれば連鎖は戻る。
  verify NG のターンでは制御フッター自体が実行されないので、**壊れたまま自分で続けることはできない**
- **誰が誰を何のために呼ぶかは `roles/*.md` の規定側**で、ブリッジは宛先の解決しかしない
  (`bots` のキーなら誰でも呼べる)。同梱の役割文では manager → worker が実装委譲、
  → manager が検収依頼、**worker ↔ reviewer が相互レビュー** (書いた本人に自己検証させない)。
  ただし**「誰が居るか」は role には書かない** — 起動中の bot・書込み権限・cwd は
  ブリッジが job ごとに「実行文脈」ブロックへ起こして role の後ろへ足す (`src/rolecontext.js`)
- **実行文脈の「呼べる相手」は出所を名乗る。** 編成が効いていれば「(このスレッドの編成)」
  または「(チャンネル既定の編成)」と書かれ、それが正本 — そこに無い相手は
  `[[handoff:...]]` で指定しても起動しない (機械的な禁止 → スレッド別の編成)。
  どちらも設定されていないスレッドでは「(いま起動している bot)」と書かれ、これは
  **技術的に届く宛先の一覧でしかない**。この場合に作者が「今回はこの bot なし」と言っても
  その bot は一覧に出続けるので、**作者の指定が優先する**と共通規定・実行文脈の両方に書いてある
  (この場合だけはプロンプト側の規律)
- **コードブロック・インラインコードの中のマーカーは実行しない**し、本文からも消さない (説明として残す)。
  閉じていないコードブロック (``` が開いたまま応答が切れた場合) は**末尾までコード扱い** —
  途中で切れた例文の末尾にフッターが残っても起動しない
- ただし**閉じ忘れに飲み込まれたフッターは警告に出す**。閉じたブロックの中のマーカーは
  「説明として書いた」ものなので黙って残すが、閉じ忘れは事故であって意図ではない —
  警告が無いと「委譲したつもりで相手が起動しない」に気付けず、いちばん見えにくい失敗になる
- モデルが書いた生の `<@id>` / `<@&id>` / `@everyone` / `@here` は `[mention:id]` のような形へ潰す。
  `allowedMentions` は通知を止めるだけで**文字列は本文に残る**ため、潰さないと受信側の起動判定を素通りできてしまう
- 送信・編集・スラッシュコマンド応答は例外なく `src/mentions.js` のラッパを通り、`allowedMentions` に
  「フッターで認可した user ID」だけを載せる (`parse: []`)。ロール・`@everyone`・返信先通知は常に無効
- **受信側の起動判定 (`src/trigger.js`) は従来どおり生 content を見る。** Discord の解析済み `mentions` は
  コードブロック内の ID や返信先も含みうるので、そちらへ寄せると逆に判定が広がる
- 改行は LF へ正規化してから解釈する (CRLF のままだと行末の `\r` でフッターが不発になる)。
  ゼロ幅スペース・NBSP などの不可視文字が紛れたフッターは**正規化して実行せず、警告する**
  — 見た目が同じで宛先が違う余地を残さないため

**投稿の完了境界。** 1 ターンの投稿順は固定されている:

```
本文 → 添付 → git 差分 → ツール軌跡 → verify → 権限通知 → メンション警告 → 制御メンション専用 1 通
```

次の agent を呼ぶのは最後の 1 通だけで、**途中で 1 つでも送信に失敗したら呼ばない**
(スレッドの archive・削除・権限喪失を含む)。**ツール軌跡だけは例外**で、投稿に失敗しても
handoff を止めない (補助情報のため。→ ツール軌跡)。
`verify` を設定したチャンネルでは、NG の job は結果まで配送したうえで最後の 1 通を出さない。欠けた文脈で次を走らせるより、そこで止めて
人間に見せる方を採っている。claude セッションは副作用済みとして保持したまま「配信失敗」で終える。
`⏳`/`⚙️` の placeholder は**配信が確定してから消す** — 先に消すと、送信に失敗したときに
失敗を伝える手段が残らない。失敗時はスレッドと placeholder の両方へ理由を出す。

**role prompt は 3 段構成。** ブリッジが `roles/_common.md` (全員共通の規定: 制御フッター・
停止契約・ツール制約・Discord 運用) → `bots.*.rolePromptFile` (その bot 固有の職務) →
**実行文脈** (ブリッジ生成: 自分・チャンネル・cwd・ファイル権限・subagent の可否・呼べる相手・通知先) の順に
連結して渡す。権限と編成の正本は `config.policy.json` 側で、role には書かない —
役割文に「この bot は read-only」と書いていた頃は、`codexSandbox` を上げても role が
古い事実を主張し続けた。前段と実行文脈が食い違ったら実行文脈が正しい、と共通規定に明記してある。

**role prompt にはプロトコル版マーカーがある。** `roles/*.md` は job ごとに読み直されるのに、
それを解釈する送信パーサはプロセス起動時のコードのまま — つまり「role だけ先に新しい」状態が
必ず生まれる (コミットしてから `/restart` するまでの窓)。job 開始時に
`<!-- communitd-protocol: N -->` と `src/protocol.js` の `PROTOCOL_VERSION` を照合し、
欠落・不一致ならモデルを起動せず「版不一致・要 restart」と表示する。照合は
**連結後ではなくファイルごと** — 連結してから 1 回だけ見ると先頭 (`_common.md`) の宣言しか
読めず、古い版のまま残った役割文を見逃す。
