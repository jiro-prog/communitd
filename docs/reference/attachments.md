# 添付

> Discord に貼られた画像とテキストファイルをモデルへ渡すときの上限と扱い。
> 入口は [README](../../README.md)、導入手順は [SETUP.md](../../SETUP.md)。

画像は PNG / JPEG / WebP (**GIF は非対応** — 下記の境界を参照)、
テキストは拡張子の許可リスト (`.md .txt .log .json .jsonl .yaml .yml .toml .csv .tsv .diff .patch .js .mjs .ts .py .sh`) に対応する。

**受信 (人間 → モデル)**
スレッド文脈に載る発言とトリガーの添付をブリッジ側で取得・検証する。期限付きの CDN URL を
モデルへ渡すことはしない (job 実行時に切れうるうえ、モデルに任意 URL を踏ませる口になる)。
画像は検証済みバイト列をランタイムの画像入力へ、テキストは本文をプロンプトの
`# 添付テキスト` セクションへ載せる。渡せなかった添付は理由付きで `# 添付` に明示するので、
「添付は無かった」と誤読されない。発言行には添付 1 件ずつ
`[添付: a.png → 画像 #1, b.md → テキスト #1]` と入力番号が付く (番号が付かない = 渡せなかったもの)。

**送信 (モデル → Discord)**
返信本文に単独行で `[[attach: 相対パス.png]]` と書くと、そのファイルを添付して送る (→ [制御マーカー](control-markers.md))。
マーカー行は本文から取り除かれる。本文を分割送信し終えてから画像を送るため、
画像の送信に失敗しても本文は届く。Discord の 1 通 10 添付制限を超える場合は複数通に分ける。

**境界**

| 項目 | 既定 | 設定キー |
| --- | --- | --- |
| 画像の枚数 / job | 4 | `limits.attachments.maxImagesPerJob` |
| 画像 1 枚の上限 | 10MB | `limits.attachments.maxBytesPerImage` |
| 画像 合計の上限 | 20MB | `limits.attachments.maxBytesTotal` |
| テキストの件数 / job | 4 | `limits.attachments.maxTextFilesPerJob` |
| テキスト 1 件のバイト上限 | 1MiB | `limits.attachments.maxBytesPerTextFile` |
| テキスト 合計のバイト上限 | 2MiB | `limits.attachments.maxTextBytesTotal` |
| テキスト 1 件の文字数上限 | 8000 | `limits.attachments.maxTextCharsPerFile` |
| テキスト 合計の文字数上限 | 16000 | `limits.attachments.maxTextCharsTotal` |
| 取得タイムアウト | 15 秒 | `limits.attachments.fetchTimeoutMs` |

- 画像とテキストは**独立した枠**で数える。zip を並べても画像枠を食わない、という設計意図と同じ理由で、テキストも画像枠を食わない
- 取得先は Discord CDN (`cdn.discordapp.com` / `media.discordapp.net`) の https のみ。**リダイレクトは一切辿らない** (302 で許可ホスト検証を素通りして内部アドレスへ届くのを塞ぐ)
- 申告 (`contentType`・拡張子) は信用せず、**形式と media type は実バイト (マジックナンバー) が決める**。画像は 3 か所で見る — 取得前の申告 `contentType`・CDN の配信ヘッダ・実バイト — の**それぞれ**が対応形式である必要はあるが、**三者が一致している必要はない**。一致要求は偽装を防がず (申告を中身へ合わせれば済む)、`contentType` を取り違えた正当な画像だけを落としていたので撤去した。SVG・HTML はシグネチャが当たらず落ち、GIF は対応形式に無いので落ちる。**`application/octet-stream` などで申告・配信された画像は、中身が正当でも取得前に落ちる**点は変わらない。テキストは `contentType` を採否に使わず、**拡張子の許可リスト AND 実バイト検査** で決める — 厳格 UTF-8 (不正バイトは U+FFFD へ潰さず拒否)、BOM は除去、NUL と改行/復帰/タブ以外の C0 制御文字を含むものはバイナリとして拒否する
- `Content-Length` は詐称されうるので、**実際に読んだバイト数**で上限を切る (超過時点で読むのをやめる)
- テキストのバイト超過は拒否、**文字数超過は先頭を残して truncate** し、省略した文字数をプロンプトに明記する。合計文字枠は**新しい添付から**配分する (直近の指示に付いたファイルを過去の大物で押し出さない)
- テキスト本文は境界行 (`--- BEGIN communitd-attachment #n: 名前 (サイズ / 発言者) ---`) で囲む。本文にその印が現れる場合は**印を伸ばして**衝突を避ける (添付の中身に偽の END 行を仕込んで後続を指示に見せかける経路を塞ぐ)
- 送信できるのは **`cwd` 配下の実在する画像だけ**。許可拡張子で絞ったうえで実バイトを検査し、拡張子と実形式の一致まで要求する (`cwd` 配下には `.env` も鍵ファイルもあるため、パス判定だけでは足りない)。`realpath` 後にも `cwd` 配下かを再確認してシンボリックリンクでの逸脱を塞ぐ
- 画像は永続保存しない。claude へは base64 で直接渡すのでファイルを作らず、codex (`exec -i`) はパスしか受けないので OS の一時ディレクトリへ書き出し、成功・失敗・停止・タイムアウトのどの経路でも `finally` で削除する
- テキストはファイルに落とさずプロンプト本文へ埋め込む。一時パスだけ渡す方式は、読取権限が足りない場合と job 終了時の削除で「モデルが読めない参照」になるため採らない (この設計上、テキスト添付は claude / codex どちらのランタイムでも同じように届く)
- **GIF は受信・送信とも拒否する**。アニメーションの解釈がランタイム依存で「静止画」として扱えると言い切れないため、初版では境界の外に置いた
