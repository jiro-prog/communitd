# ツール軌跡

> job が実際に呼んだツールを Discord に残す仕組みと、その限界。
> 入口は [README](../../README.md)、導入手順は [SETUP.md](../../SETUP.md)。

`hooks: true` のチャンネルでは、その job が**実際に実行した**ツールが 1 行でスレッドに出る:

```
🔧 ツール 21 件 (うち失敗 1): Read×11 (index.js, hooks.js, queue.js…) / Edit×4 (trace.js) / Grep×3 / PowerShell×2 (npm, git)
```

検収 (manager 役の仕事) が持つ機械的な材料は `git status` の前後差分だけで、
**「テストを実行しました」という主張が本当かは確かめられなかった**。軌跡はその証拠にあたる。
スレッドへ出た内容はそのまま次のエージェントの文脈にも載る。

- 記録は **`PostToolUse` と `PostToolUseFailure` の 2 つの hook** が実行 1 回ごとに追記する。
  **hook は何も返さないので許可判定は一切変わらない** (判定を返すのは承認カードの
  `PreToolUse` hook だけ → ツール権限の申請)
- **失敗した実行も数える。** `PostToolUse` は**成功時しか発火しない**ので、それだけだと
  落ちた `npm test` が軌跡から消えて総数が過少になる。失敗は `PostToolUseFailure` が拾い、
  0 件でなければ `(うち失敗 N)` として出す
- **拒否された呼び出しは載らない。** `PreToolUse` は実行**前**に発火するので、それを使うと
  「拒否されたシェル実行」まで軌跡に出て証拠にならない (実測: deny された Read は PreToolUse だけ
  発火し、実行後の 2 イベントは発火しない)。拒否のほうは従来どおり承認カードに出る
- 引数は短く畳む — シェルは**先頭語だけ**・ファイルは**ファイル名だけ**・`WebFetch` は
  **ドメインだけ**。`Grep` / `Glob` の検索語や `Task` のプロンプトは**出さない** (それ自体が機微になりうる)。
  秘密らしい語・長いトークン列を含む引数は要約ごと落とし、**呼び出しの回数だけ残す**。
  先頭語がフルパスのときは名前だけにする (ホスト側のディレクトリ構造を Discord へ出さない)
- 種類が多い job は上位から入るだけ出し、落とした種類数を明示する (黙って切らない)
- **claude ランタイム限定**。codex ランタイムの job では出ない — `runCodex` の返り値にツール情報が無いため
- 軌跡の投稿に失敗しても handoff は止めない (補助情報のため。本文や git 差分の失敗は従来どおり止める)
- ツール 1 回ごとに hook プロセスが 1 つ起動する。多数のツールを使う job では
  数秒ぶん遅くなる (その代わり stdout は膨らまない)
